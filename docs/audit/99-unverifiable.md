# 无法验证项与遗留风险

> **这个文件是"我没能证伪"的清单。**
>
> 这里每一条都**不是**已确认的缺陷，也**不是**已排除的风险 —— 它们是"在仓库内部
> 给不出结论"的东西。每一条都写清三件事：为什么在仓库里验不了、要验它需要什么、
> 以及它影响的是哪一类结论。
>
> 为什么单独列一份：本仓库最大的卖点是"逐条可核对"。而"可核对"这句话如果是靠
> **不写那些核不了的东西**来维持的，那它就是在骗人。所以核不了的，写在这里。

## A. README 里的自述，仓库内无法复核

## C. 只能表述成"没有发现"的那一类

| ID | 说法 | 我的表述与它的边界 |
|---|---|---|
| **U-10** | 「仓库里没有真实 PII」 | 我能说的是：**R6 提交时 `scan_sensitive.py` 与 `scan_history.py` 退出码都是 0**，且扫描器的豁免判定**只依赖值本身**（同一值在任何文件、任何一行结论相同）。我**不能**说的是"这些正则覆盖了所有形式的 PII" —— 至少两类写法按设计就绕过去了：**掩码写法**（`138xxxx1234`）既不命中也不豁免；**拆开写**（把号码拆成两段字面量）直接绕过扫描器，本仓库的 `tools/audit/test_scan_sensitive.py` 自己就是这么写的。所以这一条的正确读法是"**没有发现**"，不是"没有" |
| **U-11** | 「提交元数据已脱敏」 | `scan_commit_identity.py` 能证明的是：全部提交身份都在白名单内、没有指向本地路径的 remote。它**不能**证明提交时区不泄露地域 —— 该脚本把 `+0800` 作为 INFO 打印出来而不是错误（`GIT_AUTHOR_DATE` 统一成 `+0000` 才能消除） |
| **U-12** | 「二进制/图片不带元数据」 | 当前工作树里的 12 个图标 PNG 只含 `IHDR/IDAT/IEND`（`scan_sensitive.py` B 段输出"无元数据块"）。但那是**当前工作树**；历史里的其它二进制只由 `scan_history.py` 的同类规则覆盖 |

## D. 这一节自己的边界

- 上表**不是**风险清单，是"结论缺口清单"。判断某一条是否影响"能不能开源"时，
  要连它影响的是**哪一类结论**一起看：
  - U-1 / U-2 影响的是 **README 的可信度**；
  - U-5 影响的是"**修了也可能没用**"这件事本身；
  - U-10 影响的是"**干净**"这个词能被撑到多强。
- `99-final-report.md` 的最终结论是**把这些项全部当作仍然成立**来下的。
- 这份清单本身也会过期：任何一条被真机或语料验证之后，它应该**从本文件移出**，
  并给出转到哪份文档。目前**没有一条**已经移出。
